> 이 글은 2026년 9월 30일 Claude Code 서브에이전트 두 개로 한 번 돌린 비교다. TWG CLI는 1.3.3, Atlassian MCP는 claude.ai의 Atlassian Rovo 커넥터(원격 MCP)를 썼다. 질문 하나, 실행 한 번이라 표본이 작다. 도구의 일반적인 우열이 아니라 **이 조직·이 질문에서 관찰된 결과**로 읽어야 한다.

## 결론부터

- **Jira 결과는 같았다.** 두 쪽 모두 이슈 16건(에픽 1 + 하위 15)을 찾았고, 완료 보고 댓글 5건도 똑같이 잡았다.
- **Confluence는 TWG만 조회했다.** MCP 커넥터는 권한이 Jira용뿐이라 403이 났다.
- **검증 습관은 TWG 쪽이 나았다.** 보고자 확인, 이슈 종류, 두 조회 결과의 교차 확인까지 했다. 대신 요일을 틀렸고, 실패한 쿼리를 다시 시도하지 않아 빈틈이 하나 남았다.
- **속도는 MCP 쪽이 빨랐다.** 약 78초 대 약 123초. TWG는 명령 형식을 찾느라 도움말을 네 번 봤다.
- **둘 다 코드 작업을 보지 못했다.** 로컬 git 기록으로 세어 보니 같은 기간 본인 커밋이 70개가 넘었는데, 두 도구 모두 PR·커밋 0건이었다. 「이번 주 내가 한 일」에는 Atlassian만으로는 부족하다.

---

## 왜 비교했나

Atlassian 데이터를 에이전트에게 읽히는 길이 두 가지 있다.

| | Atlassian MCP (Rovo 커넥터) | TWG CLI |
|---|---|---|
| 형태 | 원격 MCP 서버. 도구마다 입력 스키마가 정해져 있다 | 로컬 CLI. 셸로 실행한다 |
| 설치 | 없음. 커넥터 연결만 | 설치·업그레이드 필요 |
| 쓸 수 있는 곳 | 셸이 없는 채팅 앱에서도 | 셸이 있는 환경(Claude Code 등)만 |
| 범위 | Jira·Confluence·Compass·Rovo 검색 중심 | Jira·Confluence에 더해 Bitbucket, JSM, Goals·Projects, Loom, Assets, 요약 명령(`work-tree` 등) |
| 긴 결과 | 대화에 통째로 들어온다 | 파일로 빼고 요약만 넘길 수 있다 |

표만 보면 TWG가 넓다. 실제 질문에서도 그런지 보고 싶었다. TWG에는 원래 이런 A/B 비교를 해 주는 `twg-bench-lite` 스킬이 있었는데, 비교하려던 시점에 스킬 목록에서 빠져 있어서 같은 절차를 손으로 짰다.

---

## 실험 설계

질문은 하나다.

```text
지난 7일간 내가 한 일 정리
기간: 2026-09-23 00:00 ~ 2026-09-30 (KST)
```

Claude Code에서 서브에이전트 두 개를 동시에 띄우고 같은 지시를 줬다. 다른 것은 쓸 수 있는 도구뿐이다.

| | A 그룹 | B 그룹 |
|---|---|---|
| 허용 도구 | Atlassian Rovo MCP 도구만 | `twg` CLI만 (Bash) |
| 금지 | Bash, TWG, 다른 MCP, 로컬 파일 | 모든 MCP, gh·git, 다른 소스 |
| 공통 | 읽기 전용, 로그인·설정 명령 금지, 모르는 건 빈틈으로 보고 | 같음 |

두 그룹 모두 결과 끝에 메트릭(도구 호출 수, 실패, 가장 큰 결과 크기, 포착률 자체 추정)과 한계를 적게 했다.

기준값은 두 도구 밖에서 따로 잡았다. 로컬 git 기록에서 같은 기간 본인 커밋 수를 저장소별로 셌다.

## 결과 1 — 무엇을 찾았나

| 항목 | A: MCP | B: TWG |
|---|---|---|
| Jira 이슈 | 16건 (완료 6 · 할 일 9 · 에픽 1) | 16건 (같음) |
| 활동 날짜 | 모두 하루(9/29)에 몰림 | 같음 |
| 완료 보고 댓글 | 5건 | 5건 (댓글 ID까지) |
| 보고자 확인 | 안 함 (담당자만) | 함 (16건 모두 본인) |
| 할 일 이슈 종류(Story/Task) | 일부만 | 전부 |
| Confluence | ❌ 403 | ✅ 조회됨, 0건 |
| 남의 이슈에 남긴 활동 | ✅ 확인함, 0건 | ⚠️ 쿼리 실패 뒤 재시도 안 함 |
| 결과 교차 확인 | 없음 | 두 조회의 16건이 정확히 일치 |
| 요일 | 9/29 (화) ✅ | 9/29 (월) ❌ |

### A 그룹의 403

```text
Current user not permitted to use Confluence
```

커넥터에 부여된 범위가 `read:jira-work`, `write:jira-work`뿐이었다. 도구 목록에는 Confluence 도구가 보이는데 호출하면 막힌다. **도구가 목록에 있다고 권한이 있는 건 아니다.** 커넥터 쪽에 Confluence 범위를 추가해야 한다.

### 두 그룹이 똑같이 낸 실패

```text
issuekey IN updatedBy(currentUser(), "2026-09-23")
→ Error in the JQL Query: Expecting ')' or ',' but got '('. (line 1, character 34)
```

`updatedBy()` 안에 `currentUser()`를 넣을 수 없다. 여기서 두 그룹이 갈렸다.

- A는 계정 ID를 직접 넣어 다시 돌렸다. 담당·보고·워처 밖에서 본인이 건드린 이슈가 0건임을 확인했다.
- B는 다른 쿼리(`work query`)로 우회했다. 16건 교차 확인은 했지만, 남의 이슈에 남긴 활동은 끝내 훑지 못했다.

도구 차이라기보다 에이전트가 실패 뒤에 무엇을 했느냐의 차이다. 한 번 돌린 실험에서는 이런 우연이 결과를 흔든다.

## 결과 2 — 비용

| 항목 | A: MCP | B: TWG |
|---|---|---|
| 걸린 시간 | 약 78초 | 약 123초 |
| 도구 호출 | 10회 (실패 3) | 19회 (도움말 4, 실패 1) |
| 서브에이전트 토큰 | 약 142K | 약 132K |
| 가장 큰 결과 | 약 70K자 | 약 84KB |

- **A가 빨랐다.** 도구 스키마가 정해져 있어 바로 호출한다.
- **B는 도움말 비용을 냈다.** `twg help describe <명령>`으로 플래그를 확인하는 단계가 네 번 들어갔다. 대신 토큰은 조금 덜 썼다.
- **A는 큰 결과 하나를 버렸다.** 넓게 건 쿼리의 결과가 70K자를 넘어 호스트가 자동으로 파일로 뺐는데, 이 실험에서 A 그룹은 로컬 파일 읽기를 막아 둬서 쓰지 못했다. 실험 설계가 만든 손해다. 실제 사용에서는 읽으면 된다.

## 결과 3 — 둘 다 못 본 것

같은 기간 로컬 git 기록의 본인 커밋이다.

| 저장소 | 9/28 | 9/29 |
|---|--:|--:|
| 기록용 저장소 (원격 없음) | 26 | 20 |
| 프런트엔드 저장소 (GitHub) | 3 | 20 |
| 기타 저장소 두 곳 | 2 | — |

- **9/28은 두 도구 모두 「활동 없음」이었다.** 실제로는 커밋이 31개였다. 대부분 원격이 없는 기록 저장소라 어떤 도구도 볼 수 없다.
- **GitHub 저장소도 TWG가 0건으로 봤다.** Jira 댓글에 커밋 해시가 네 개나 적혀 있었는데 PR·커밋 조회는 비어 있었다. 이 조직의 GitHub가 TWG에 연결·인덱싱되지 않은 것으로 보인다. 「TWG는 코드·PR 조회에 강하다」는 장점은 **SCM 연동이 된 조직에서만** 성립한다.

두 그룹의 포착률 자체 추정도 이걸 알고 있었다. A는 전체 업무의 30~40%, B는 60~70%로 봤다. 기준값과 비교하면 둘 다 후하게 잡은 편이다.

## 어느 쪽을 쓸까

| 상황 | 고를 것 |
|---|---|
| Jira 이슈 하나 읽기, 댓글 달기 | MCP. 빠르고 설치가 없다 |
| Confluence까지 봐야 함 | 지금 연결 상태로는 TWG. MCP는 커넥터에 범위를 추가하면 된다 |
| Bitbucket, JSM, Goals, Assets | TWG만 된다 |
| 여러 소스를 가로지르는 요약 | TWG의 요약 명령이 유리. 단 SCM 연동이 전제 |
| 「이번 주 내가 한 일」 | 둘 다 부족. git·GitHub 기록을 함께 봐야 한다 |

주간 회고처럼 코드 작업이 큰 질문은 Atlassian 도구 하나로 끝내지 말고, GitHub·git 기록을 같이 모으는 쪽으로 짜는 게 맞다.

## 아직 확인하지 않은 것

- **반복 실행.** 한 번씩만 돌렸다. 실패 뒤 재시도 여부처럼 에이전트 판단에 따라 결과가 바뀌는 부분이 있어서, 같은 질문을 여러 번 돌려야 도구 차이와 우연을 가를 수 있다.
- **다른 질문.** 이슈 하나의 연결 관계 찾기, 담당자 찾기처럼 TWG의 요약·그래프 기능이 더 드러나는 질문은 해 보지 않았다.
- **Confluence 범위를 준 MCP.** A 그룹의 Confluence 결과는 권한 문제로 비어 있다. 범위를 추가하면 격차가 줄어들 수 있다.
- **TWG의 GitHub 연동 상태.** PR 0건이 연동 부재 때문인지 인덱싱 지연 때문인지 확인하지 않았다.
- **`twg-bench-lite` 스킬.** 원래의 채점 방식으로 돌리지 못했다. 이 글의 기준은 내가 정한 것이다.
