## 결론부터

**맥 2대(tmux 3.7)와 리눅스 3대(tmux 3.4)에 분기 없는 `.tmux.conf` 하나를 그대로 쓸 수 있다.** 그리고 tmux 안에서 커서를 깜박이게 하려면 옵션 두 줄이 **둘 다** 필요하다.

```tmux
set -g cursor-style blinking-block
set -as terminal-overrides ',xterm*:cnorm=\E[?25h'
```

| 설정 | tmux가 터미널로 보내는 신호 | 결과 |
|---|---|---|
| 기본값 | `\E[?12l`만 반복 | 깜박임 꺼짐 |
| `cursor-style blinking-block`만 | `\E[1 q` 직후 매번 `\E[?12l` | 켜졌다가 바로 꺼짐 |
| **두 줄 모두** | `\E[1 q`만 나감 | **깜박임 유지** |

첫 줄만 넣고 "안 되네" 하고 포기하기 쉬운데, 원인은 두 번째 줄이 막는 곳에 있다.

## 출발점: 머신마다 설정이 달랐다

SSH로 붙는 머신 다섯 대의 `~/.tmux.conf`를 모아 보니 두 종류였다.

| 구성 | OS | tmux | 설정 |
|---|---|---|---|
| 맥 2대 | macOS arm64 | 3.7 | 공통본 4줄 |
| 클라우드 VM 2대 | Ubuntu aarch64 | 3.4 | 공통본 4줄 |
| 리눅스 데스크톱 1대 | Ubuntu x86_64 | 3.4 | 공통본 + 8줄 |

충돌하는 값은 없었다. 한 대에만 있는 추가 설정을 나머지에 얹으면 된다. 문제는 **버전과 OS 차이 때문에 한쪽에서만 깨지는 설정이 있는가**였다.

## 통합한 설정 전문

```tmux
# 256색 + tmux 전용 terminfo (italic 등 지원)
set -g default-terminal "tmux-256color"

# 바깥 터미널이 truecolor를 지원하면 그대로 전달
set -as terminal-features ",*256col*:RGB,xterm-ghostty:RGB"

# 마우스로 pane 선택, 크기 조절, 로그 스크롤
set -g mouse on

# 이전 출력 보관 줄 수
set -g history-limit 100000

# Esc 입력 지연 최소화 (tmux 3.4 기본값 500ms → vim 반응 지연)
set -sg escape-time 10

# 포커스 이벤트 전달 (vim/nvim 자동 reload 등)
set -g focus-events on

# 클립보드 연동을 지원하는 터미널에서 사용
set -g set-clipboard on

# 이미지 프로토콜 등 이스케이프 시퀀스를 바깥 터미널로 통과
set -g allow-passthrough on

# window/pane 번호를 1부터 시작
set -g base-index 1
setw -g pane-base-index 1

# 중간 window가 사라지면 번호를 다시 정리
set -g renumber-windows on

# window 이름을 실행 중인 명령으로 자동 변경하지 않음
setw -g automatic-rename off

# 커서: 깜박이는 블록
set -g cursor-style blinking-block

# cnorm의 \E[?12l(깜박임 끄기)을 빼서 tmux가 커서 깜박임을 끄지 않게 함
set -as terminal-overrides ',xterm*:cnorm=\E[?25h'

# prefix + r: 설정 다시 읽기
bind r source-file ~/.tmux.conf \; display "reloaded"
```

## 버전·OS 차이 점검

### 3.4 vs 3.7

- **전부 3.4에서 동작한다.** 가장 최근에 생긴 축인 `allow-passthrough`도 3.3부터 있고, `cursor-style`도 3.4에 있다.
- **`escape-time`은 3.4에서 사실상 필수다.** 3.4의 기본값은 500ms라 vim에서 Esc를 누르면 반 박자 늦는다. 이후 버전은 기본값이 낮아졌지만, 명시해 두면 버전과 무관하게 같은 동작이 보장된다.
- **`terminal-overrides ...:RGB`는 옛 방식이다.** 3.2부터 `terminal-features`가 권장이라 truecolor는 그쪽으로 옮겼다.

### macOS

가장 걱정한 건 `default-terminal "tmux-256color"`였다. 예전 macOS의 시스템 ncurses에는 `tmux-256color` terminfo가 없어서, tmux 안에서 `/usr/bin` 도구가 `unknown terminal`을 내는 경우가 있었다. 확인해 보니 지금 macOS에는 있었다.

```bash
/usr/bin/infocmp -x tmux-256color >/dev/null && echo ok
```

그래서 **`if-shell 'uname | grep -q Darwin'` 같은 분기 없이** 한 파일로 끝났다. 오래된 macOS라면 이 확인부터 하고, 없으면 맥에서만 `screen-256color`를 쓰면 된다.

### 동작이 바뀌는 두 설정

`base-index 1`과 `automatic-rename off`는 호환성 문제가 아니라 취향 문제다. 기존에 0번부터 쓰던 머신은 `prefix + 0` 습관이 바뀐다. 설정을 다시 읽어도 **이미 있는 window 번호는 그대로**고, 새 세션부터 1번으로 시작한다.

## 배포

어려울 게 없다. 백업, 복사, 검증, 반영 순서만 지키면 된다.

```bash
for h in host-a host-b host-c host-d; do
  ssh "$h" 'cp -p ~/.tmux.conf ~/.tmux.conf.bak-$(date +%Y%m%d)' \
    && scp -q ~/.tmux.conf "$h":.tmux.conf
done
```

검증은 **기존 세션과 분리된 소켓**으로 임시 서버를 띄워서 한다. 문법 오류가 있으면 여기서 드러나고, 실제 세션은 건드리지 않는다.

```bash
tmux -L cfgverify -f ~/.tmux.conf new-session -d \; \
  show -gv base-index \; show -sv escape-time \; show -gwv cursor-style
tmux -L cfgverify kill-server
```

통과하면 실행 중인 서버에 반영한다.

```bash
tmux has-session 2>/dev/null && tmux source-file ~/.tmux.conf
```

맥에서 SSH로 원격 실행할 때 하나 주의할 점이 있다. **비대화형 SSH 셸에는 `/opt/homebrew/bin`이 PATH에 없어서** `tmux: command not found`가 뜬다. 설치가 안 된 게 아니다. 원격 명령 앞에 `export PATH=/opt/homebrew/bin:$PATH`를 붙이면 된다.

## 본론: 커서가 안 깜박인다

터미널은 Ghostty다. tmux 밖에서는 커서가 깜박이는데 tmux 안에만 들어가면 멈춘다. 블록 커서가 깜박이길 원해서 `cursor-style blinking-block`을 넣었지만 여전히 멈춰 있었다.

### 커서를 제어하는 방법은 두 가지다

| 방식 | 시퀀스 | 성격 |
|---|---|---|
| DECSCUSR | `CSI Ps SP q` (`\E[1 q` = 깜박이는 블록, `\E[2 q` = 멈춘 블록, `\E[0 q` = 기본값) | 현대식. 모양과 깜박임을 함께 지정하고 기본값으로 되돌릴 수 있다 |
| DEC mode 12 | `\E[?12h` 켜기 / `\E[?12l` 끄기 | 구식. 깜박임 on/off만 있고 "기본값"이 없다 |

### tmux가 뭘 보내는지 직접 캡처했다

추측 대신 바이트를 봤다. 격리된 tmux 서버에 `script`로 클라이언트를 붙이고, 셸 입력, pane 분할, vi 실행과 종료를 흘린 뒤, 출력에서 커서 관련 시퀀스만 뽑았다.

```bash
tmux -L probe -f ./test.conf new-session -d -x 80 -y 24
( sleep 8 | TERM=xterm-256color script -q cap.bin tmux -L probe attach >/dev/null 2>&1 ) &
sleep 1.5; tmux -L probe send-keys 'echo hi' Enter
sleep 0.5; tmux -L probe split-window
sleep 0.5; tmux -L probe send-keys 'vi' Enter
sleep 0.7; tmux -L probe send-keys Escape ':q!' Enter
sleep 0.7; tmux -L probe display-message ZZMARKZZ
sleep 0.7; tmux -L probe kill-server

# 종료 시 복원 시퀀스를 빼기 위해 마커 이전만 본다
LC_ALL=C perl -0777 -ne 's/ZZMARKZZ.*//s;
  @m = /(\e\[[0-9]? q|\e\[\?12[lh]|\e\[\?12;25h)/g;
  for (@m) { s/\e/^[/; print "$_ " } print "\n"' cap.bin
```

캡처를 짜면서 함정이 두 개 있었다.

- **`script`의 stdin을 `/dev/null`로 주면 안 된다.** EOF가 pty에 `^D`로 전달돼 pane 셸이 종료되고, 세션이 통째로 사라진다. `sleep 8 |`로 입력을 열어 둔 이유다.
- **클라이언트 종료 시 tmux는 커서를 원래대로 되돌리는 시퀀스를 보낸다.** 이걸 섞으면 결과를 잘못 읽는다. 종료 직전에 `display-message`로 마커를 찍고 그 앞까지만 봤다.

결과는 이렇다.

```
기본값          ^[[?12l ^[[?12l ^[[?12l ^[[?12l ^[[?12l ...
blinking-block  ^[[?12l ^[[1 q ^[[?12l ^[[1 q ^[[?12l ^[[2 q ^[[?12l ^[[1 q ^[[?12l ...
두 줄 모두      ^[[1 q ^[[1 q ^[[2 q ^[[1 q ^[[1 q ^[[1 q ...
```

`blinking-block`만 넣으면 **`\E[1 q`로 깜박임을 켠 직후 `\E[?12l`로 다시 끈다.** 이게 반복된다.

(중간의 `^[[2 q`는 vi가 요청한 멈춘 블록이다. vi를 끄면 다시 `^[[1 q`로 돌아온다. 앱별 커서 모양은 정상적으로 전달된다는 뜻이다.)

### 범인: cnorm

`\E[?12l`은 어디서 왔을까. tmux는 커서를 정상 표시 상태로 되돌릴 때 바깥 터미널 terminfo의 `cnorm`을 보낸다.

```bash
$ infocmp -x -1 xterm-256color | grep -E 'cnorm|cvvis|Ss=|Se='
	cnorm=\E[?12l\E[?25h,
	cvvis=\E[?12;25h,
	Se=\E[2 q,
	Ss=\E[%p1%d q,
```

**`cnorm` 앞의 `\E[?12l` 여섯 바이트가 깜박임 끄기다.** 캡처에서 봤듯 tmux는 화면을 갱신할 때마다 이걸 보낸다.

### 왜 Ghostty는 이걸 따르나

Ghostty 설정 문서의 `cursor-style-blink` 항목에 답이 있다.

> If this is not set at all (`null`), then Ghostty will respect DEC Mode 12 (AT&T cursor blink) as an alternate approach to turning blinking on/off. If this is set to any value other than null, DEC mode 12 will be ignored but `DECSCUSR` will still be respected.

소스(`src/termio/stream_handler.zig`)의 주석은 이 설계 이유를 길게 설명한다. 요약하면 이렇다. mode 12는 "기본값으로 되돌리기"가 없어서, 구식 프로그램이 한 번 끄면 다시 켜질 방법이 없다. 그래서 사용자가 깜박임 기본값을 명시했을 때만 mode 12를 무시한다.

이 설정을 비워 두면(기본) Ghostty는 mode 12를 따르고, tmux의 `cnorm`이 깜박임을 끈다. **tmux 밖에서는 깜박이고 안에서만 멈추는 이유가 정확히 이것이다.**

## 해결: 어느 쪽을 고칠까

| 방법 | 위치 | 장단점 |
|---|---|---|
| `terminal-overrides`로 `cnorm`에서 `\E[?12l` 제거 | tmux | **어떤 터미널로 붙어도 동작한다.** 여러 머신에 같은 파일을 배포하는 구조와 맞는다 |
| `cursor-style-blink = true` | Ghostty | mode 12를 무시하므로 Ghostty에서는 통한다. 하지만 다른 터미널로 붙으면 문제가 그대로 남는다 (이 방법은 직접 검증하지 않았다) |

tmux 쪽을 택했다.

```tmux
set -g cursor-style blinking-block
set -as terminal-overrides ',xterm*:cnorm=\E[?25h'
```

`cnorm`에서 `\E[?25h`(커서 보이기)만 남기고 깜박임 끄기를 뺐다. 깜박임 제어는 DECSCUSR(`cursor-style`)에게만 맡긴다.

리눅스 tmux 3.4에서도 같은 캡처를 돌렸다. 리눅스 `script`는 문법이 달라 `script -qfc "tmux -L probe attach" cap.bin` 형태로 바꿨고, 결과는 맥과 같았다.

```
^[[1 q ^[[1 q ^[[2 q ^[[1 q ^[[1 q ^[[1 q ^[[1 q ^[[1 q
```

`\E[?12l`은 한 번도 나가지 않았다.

### 적용 후에도 이상하다면

- **붙어 있던 화면이 그대로면** detach 후 다시 attach한다.
- **프롬프트에서만 막대 커서로 바뀌면** 셸 통합이 DECSCUSR을 보내는 것이다. Ghostty라면 `shell-integration-features = no-cursor`로 끈다.
- **zsh vi 모드 플러그인**도 모드 전환마다 커서 모양을 보낸다. 셸 설정에 `\e[2 q` 같은 문자열이 있는지 확인한다.
