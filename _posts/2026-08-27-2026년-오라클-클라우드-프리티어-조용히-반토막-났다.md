## 요약

- 2026년 6월 15일부로 **Always Free의 ARM 할당량이 절반**이 됐다. 4 OCPU / 24GB → **2 OCPU / 12GB**.
- **PAYG(종량제) 계정은 기존 4/24를 유지**한다. 축소는 신규 무료 계정에만 적용된다.
- 그럼에도 **월 10TB 아웃바운드**는 그대로다. 이게 여전히 이 프리티어의 최대 무기다.
- 홈 리전은 사실상 못 바꾼다. **춘천(South Korea North)에서는 ARM 인스턴스를 만들 수 없다.**
- 체크카드·선불카드·가상카드로는 가입이 안 된다.

---

## 1. 무엇이 달라졌나

2026년 6월 15일, Oracle이 Always Free 계정의 Ampere A1 할당량을 조용히 줄였다. 별도 공지 없이 문서만 바뀌어서 한동안 커뮤니티에서 "내 계정만 이상한가" 하는 글이 이어졌다.

| | 이전 | 2026-06-15 이후 |
|---|---|---|
| ARM (Ampere A1) | 4 OCPU / 24GB | **2 OCPU / 12GB** |
| 월 OCPU 시간 | 3,000 | **1,500** |
| 월 GB 시간 | 18,000 | **9,000** |

공식 문서의 현재 표현은 이렇다.

> All tenancies get the first 1,500 OCPU hours and 9,000 GB hours per month for free for VM instances using the VM.Standard.A1.Flex shape. For Always Free tenancies, this is equivalent to 2 OCPUs and 12 GB of memory.

**중요한 예외가 하나 있다.** Oracle 서포트 답변에 따르면 이 축소는 신규 무료 계정에만 적용되고, **PAYG·Enterprise 등 유료 테넌시는 4 OCPU / 24GB를 그대로 유지**한다. 뒤에서 다시 다루겠지만, 이게 "무료로 쓰면서도 PAYG로 전환하는" 전략의 근거다.

> ⚠️ 지금 한국어로 검색되는 오라클 프리티어 글의 상당수가 "4코어 24GB 무료"를 전제로 쓰여 있다. 2026년 6월 이전 글이라면 사양 부분은 걸러 읽어야 한다.

## 2. 지금 무료로 받을 수 있는 것

2026년 8월 기준, 공식 문서에서 확인한 Always Free 항목 전체다.

### 컴퓨트

| 셰이프 | 할당량 |
|---|---|
| **VM.Standard.A1.Flex** (ARM, Ampere Altra) | 총 2 OCPU / 12GB — 1대 몰빵 또는 1코어씩 2대 |
| **VM.Standard.E2.1.Micro** (AMD EPYC) | 2대, 각 1/8 OCPU + 1GB |

두 셰이프는 **별개 할당량**이라 동시에 쓸 수 있다. 최대 4대까지 가능하다. 자세한 조합 전략은 [4편](/dev/2026/08/27/arm과-amd-둘-다-쓸-수-있다-오라클-프리티어-셰이프-정리/)에서 다룬다.

### 스토리지

| 항목 | 할당량 |
|---|---|
| 블록 볼륨 | 부팅+블록 합쳐 **총 200GB** |
| 볼륨 백업 | 5개 |
| 오브젝트/아카이브 스토리지 | 20GB + API 요청 5만건/월 |

부팅 볼륨 최소 크기가 47GB(기본 50GB)라, **4대를 만들면 200GB를 전부 소진**한다.

### 네트워크 — 여기가 진짜 하이라이트

| 항목 | 할당량 |
|---|---|
| **아웃바운드 트래픽** | **월 10TB** |
| Flexible Load Balancer | 1개 (10Mbps) |
| Network Load Balancer | 1개 |
| VCN | 2개 |
| Site-to-Site VPN | IPSec 연결 50개 |

**월 10TB.** AWS 프리티어의 100GB와 비교하면 100배다. 개인 프로젝트 수준에서는 사실상 무제한이고, 이 항목만으로도 오라클 프리티어를 쓸 이유가 된다. 그리고 이번 축소에서 **여기는 건드려지지 않았다.**

### 데이터베이스

| 항목 | 할당량 |
|---|---|
| Autonomous Database | 2개 (각 1 OCPU / 20GB) |
| MySQL HeatWave | 1개 노드, 50GB + 백업 50GB |
| NoSQL Database | 읽기·쓰기 각 월 1억 3300만, 테이블 3개 × 25GB |

### 관측·관리

| 항목 | 할당량 |
|---|---|
| Monitoring | 수집 5억 / 조회 10억 데이터포인트 |
| Logging | 월 10GB |
| Notifications | HTTPS 100만건 / 이메일 1000건 |
| Email Delivery | 월 3,000통 |
| Vault | 소프트웨어 키 무제한, HSM 20개, 시크릿 150개 |
| Bastion | 무료 |
| Resource Manager (Terraform) | 스택 100개 |

Vault가 무료라는 점은 의외로 잘 안 알려져 있다. API 키를 코드에 박는 대신 여기 넣으면 된다.

## 3. 가입하기

### 준비물

- 이메일
- 휴대폰 (SMS 인증)
- **해외결제 가능한 신용카드**

본인확인용 $1 가승인만 잡히고 실제 청구는 없다. 그런데 카드에서 막히는 경우가 가장 많다.

> ❌ **체크카드 · 선불카드 · 가상카드 · 일회용 카드 불가**

오라클 FAQ에 명시된 제약이다. 요즘 많이 쓰는 앱 기반 가상카드나 트래블카드도 대부분 거절된다. 정식 신용카드를 준비하자.

### 홈 리전 — 가장 중요한 선택

가입 화면에서 홈 리전을 고르는데, **여기가 이 글에서 가장 중요한 부분**이다.

- Always Free 인스턴스는 **홈 리전에서만** 생성된다
- 홈 리전은 **나중에 사실상 못 바꾼다** (변경 요청 자체가 까다롭다)

한국이라면 선택지는 둘이다.

| 리전 | ARM 인스턴스 |
|---|---|
| South Korea Central (**서울**) | ✅ 가능 |
| South Korea North (**춘천**) | ❌ **불가** |

공식 문서에 명시돼 있다.

> You can create OCI Ampere A1 Compute instances in any availability domain, **except South Korea North (Chuncheon)**.

춘천을 고르면 ARM을 아예 못 만든다. 무조건 피하자.

서울도 ARM 재고가 만성적으로 부족해서 인스턴스 생성이 잘 안 된다. 이 문제는 [2편](/dev/2026/08/27/out-of-capacity와-유휴-회수-오라클-프리티어-두-관문-뚫기/)에서 본격적으로 다룬다.

용도에 따라 아시아 밖을 고르는 게 나은 경우도 있는데, 그 판단 근거는 [별도 글](/dev/2026/08/27/claude-api-지연-실측-에이전트-루프에서-서버-리전이-중요한-이유/)에서 실측과 함께 정리했다.

### 30일 $300 크레딧의 함정

가입하면 30일간 쓸 수 있는 $300 크레딧이 붙는다. 이걸로 만든 **유료 리소스는 크레딧 소진·기간 만료 시 회수**된다.

특히 주의할 점: 체험 기간에 ARM을 4 OCPU로 만들어두면, 무료 전환 시 한도(2 OCPU)를 초과하므로 **모든 A1 인스턴스가 비활성화되고 30일 후 삭제**된다.

> If you have more OCI Ampere A1 Compute instances provisioned than are available for an Always Free tenancy, all existing OCI Ampere A1 Compute instances are disabled and then deleted after 30 days, unless you upgrade to a paid account.

**처음부터 "Always Free-eligible" 배지가 붙은 리소스만 만드는 습관**을 들이는 게 안전하다. 콘솔에서 인스턴스를 만들 때 셰이프 옆에 이 배지가 표시된다.

## 4. 첫 인스턴스 만들기

Compute → Instances → Create Instance 순서로 들어간다.

| 항목 | 권장 |
|---|---|
| Image | Ubuntu 24.04 LTS 또는 Oracle Linux 9 |
| Shape | Ampere → `VM.Standard.A1.Flex` → 2 OCPU / 12GB |
| Networking | 새 VCN, 퍼블릭 서브넷, "Assign a public IPv4 address" 체크 |
| SSH key | 로컬에서 `ssh-keygen -t ed25519` 후 공개키 붙여넣기 |

ARM 셰이프를 고르면 이미지도 자동으로 aarch64 버전이 선택된다.

접속은 이렇게 한다.

```bash
# Ubuntu
ssh -i ~/.ssh/id_ed25519 ubuntu@<공인IP>

# Oracle Linux
ssh -i ~/.ssh/id_ed25519 opc@<공인IP>
```

여기까지 됐다면, 다음 관문은 **웹 포트가 안 열리는 문제**다. 오라클은 방화벽이 두 겹이라 반드시 걸린다. [3편](/dev/2026/08/27/포트를-열었는데-왜-접속이-안-되나-오라클의-이중-방화벽/)에서 다룬다.

## 5. 계정 유지 시 주의사항

- **계정당 1개.** 다중 계정 생성 시도는 약관 위반이고 실제 정지 사례가 많다.
- **30일 이상 방치 금지.** 유휴 계정은 정지·종료 대상이다.
- **유휴 인스턴스도 회수 대상이다.** 조건과 회피법은 [2편](/dev/2026/08/27/out-of-capacity와-유휴-회수-오라클-프리티어-두-관문-뚫기/)에서.
- 현재 할당량은 콘솔에서 확인할 수 있다. **Governance & Administration → Tenancy Management → Limits, Quotas and Usage**

## 정리

사양이 절반으로 줄었지만, 2 OCPU / 12GB ARM에 월 10TB 트래픽은 여전히 개인 프로젝트용으로 넉넉하다. 같은 급을 유료로 빌리면 월 2~3만원은 나간다.

다만 시작하려면 세 관문을 통과해야 한다.

1. 신용카드와 홈 리전 선택 ← 이 글
2. `Out of host capacity` 에러와 유휴 회수 ← [2편](/dev/2026/08/27/out-of-capacity와-유휴-회수-오라클-프리티어-두-관문-뚫기/)
3. 이중 방화벽 ← [3편](/dev/2026/08/27/포트를-열었는데-왜-접속이-안-되나-오라클의-이중-방화벽/)
